# Protect mode — real benchmark (held-out test sets)

_Generated by `make protect-bench` (`python -m modes.protect.evaluate --bench`). Do not edit numbers by hand._

## Methodology

- **URL data:** PhiUSIIL Phishing URL Dataset (Prasad & Chandra, 2023), UCI ML Repository id 967, CC BY 4.0 — https://archive.ics.uci.edu/dataset/967 . Random sample of 2,500 phishing + 2,500 legitimate unique URLs (seed 42).
- **SMS data:** SMS Spam Collection v.1 (Almeida & Hidalgo, 2011), UCI id 228, CC BY 4.0 — https://archive.ics.uci.edu/dataset/228 . All 5,574 messages (747 spam / 4,827 ham); spam is treated as 'scam'.
- **Extra URL check:** OpenPhish community feed (https://openphish.com/feed.txt), downloaded 2026-10-21, all live phishing → recall only. Kept locally in `raw/`, not redistributed.
- **Split:** stratified 80/20 train/test, fixed seed 42 (column `split` in each benchmark.csv).
- **Positive prediction:** verdict is `suspicious` or `dangerous` (score ≥ 35).
- **URL detector** is rule-based (no training). Any rule tuning was done by looking at TRAIN-split errors only.
- **SMS Naive Bayes** is fitted on the TRAIN split only and scored on TEST. Rules were never tuned on TEST.

## Detector changes made for this benchmark

- **URL:** added one feature, `free_hosting` (+35): page hosted on free hosting / site-builder / IPFS gateways (web.app, firebaseapp.com, repl.co, glitch.me, netlify.app, wixsite, IPFS…). Found by reading TRAIN-split false negatives only. Held-out test recall before the change: 0.162 (F1 0.279); after: see table above.
- **SMS:** tried relaxing how far Naive Bayes alone can push a message (TRAIN recall 0.754 → 0.765) — gain too small and it hurt the India sample set, so it was **reverted**. Rules+NB is lower than NB-only because the fusion deliberately caps NB when no rule fires (designed for the 42-row sample model). That trade-off is reported, not hidden.
- Remaining URL misses are mostly plain domains with no path (e.g. `http://www.example-shop.com`): lexical rules cannot tell these apart without page content or reputation data — future work.


## Voice — NOT a benchmark

Voice-clone detection is **demonstration-grade only**: a signal heuristic checked on 8 synthetic demo clips (accuracy 1.00). No public anti-spoofing corpus (e.g. ASVspoof) was used, so no real-world claim is made.

## What these numbers mean (and don't)

- They are honest held-out numbers on public datasets the detectors were not tuned on.
- PhiUSIIL legitimate URLs are mostly site homepages while phishing URLs often have deep paths, so URL-shape cues are easier here than in real traffic. Real-world precision is likely lower.
- The UCI SMS corpus is UK/Singapore SMS from ~2010 (prize/ringtone spam), not Indian 2020s scams (digital arrest, UPI, KYC). The India-specific rules are mostly *not exercised* by it; India-context performance is only shown on the small **synthetic** `datasets/sms/sms_samples.csv` set, which is not a benchmark.
- Single split, single seed; no confidence intervals. With ~150 spam test messages, ±3–4 points of recall is within noise.
- No adversarial / evasion testing was done.
